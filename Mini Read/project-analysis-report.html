能读，还没读完。

Mini Read 已经是一个可以日常使用的 EPUB 阅读器：共享 TextKit 分页、目录锚点、书签、阅读统计和导入去重都做得相当扎实。但它的「周边层」明显跑在核心前面——高亮、笔记、全书搜索、导出几乎还是空壳，设置页里还有一批开关没有接线。

一句话结论：核心阅读链路约 85 分，周边能力约 45 分，综合 70/100。最值得做的不是再加功能，而是把已经存在的入口真正接上，并补上标注与无障碍这两块阅读器的地基。

01 / OVERVIEW

先给结论

这是一个「核心做得比外壳好」的项目。阅读器主链路有清晰的架构收口和大量踩坑注释；真正的问题集中在功能闭环、设置接线和可访问性，而不是分页算法本身。

做得好的

阅读引擎有工程厚度

共享 NSTextStorage / NSLayoutManager、跨页首行缩进、稳定摘要缓存、LRU pin 当前章、首屏后全书页码索引——这些都不是 Demo 级实现。

明显短板

「看起来有」的功能很多

高亮回调从未被调用，笔记页签被刻意拿掉，导出/分享只有开关，全书搜索不存在；设置页还有 30+ 个字段没有消费者。

最大风险

标注与路径会咬人

标注直接改共享 NSTextStorage 且不持久化；书籍存绝对 URL；正文没有 VoiceOver 元素。三者都触及阅读器的地基。

建议顺序

先闭环，再扩展

P0 修标注、路径、无障碍与测试；P1 做全书搜索、笔记 UI、设置清理；P2 再补导出、本地化、诊断与 CSS 子集。

3
如果只做三件事：① 把标注做成可持久化的真功能（模型 + 菜单 + 绘制 + 设置消费）；② 把书籍路径改成相对路径并迁移；③ 给正文补 VoiceOver 与 iPhone 选择。三件都做完，这个 App 的「完成度」会比再加十个设置页更明显。

打开一本书的 8 步

这条链路是当前工程最值得保留的部分：解析、排版、缓存、上屏各自有明确边界。

  1. 书库点击BookContentView 接收 bookItem，建立阅读会话。
  2. 目录加载ContentsPanelViewModel.loadEPUBAsync 解析 EPUB。
  3. 阅读顺序EPUBBook + EPUBNavigation → allSrcs / titleBySrc / anchors。
  4. 阅读器外壳PageViewControllerRepresentable 创建 ViewController。
  5. 按章加载loadChapterAsync 先查 PaginationCache，再后台排版。
  6. 解析与排版ChapterRender：HTML → blocks → NSAttributedString → ChapterLayout。
  7. 缓存与建页PaginationCache 落盘；ChapterLRUCache pin 当前章。
  8. 上屏与回写TextVC / TextRenderView 绘制；reportVisibleLocation 回写进度与书签。

四个值得保留的设计决策

01

共享 TextKit

一个 NSTextStorage + 一个 NSLayoutManager 挂多个 container，段落首行缩进和跨页选中在整章范围内一次判定。

02

稳定摘要

PaginationConfig.stableDigest 用 SHA-256 而不是 hashValue，跨进程缓存键才真正命中。

03

LRU pin 当前章

淘汰永远跳过正在上屏的章，避免 VC 被回收后手势、进度、书签静默失效。

04

首屏优先

全书页码索引等第一页真正上屏后才启动，并带 0.35s 合并窗，不让首屏和索引抢主线程。

06 / RISKS

已知风险与回归点

这些不是「代码风格」问题，而是会在真实用户、真实书籍或系统升级时暴露出来的问题。按严重度排序。

高标注直接修改共享 NSTextStorage，且没有持久化+

证据：TextVC.swift:322-342 的 applyHighlight / applyUnderline 直接对 chapterLayout.textStorage 加属性；TextRenderView.swift:28-31 的回调从未被任何代码调用。

影响：高亮无法跨页/跨章/跨启动保留；修改共享 storage 可能触发布局失效和页码漂移；没有撤销；设置里的颜色/透明度完全不生效。

建议：建立 Annotation 模型（bookKey、src、字符范围、原文、颜色、样式、笔记），绘制时用 temporary attributes 或独立 overlay，不改底层分页文本。

高书籍路径以绝对 URL 持久化+

证据：BookModel.swift:14-16 直接存 bookExtrSubdir / bookBackupdir / resourceBaseURL 三个 URL。

影响：App 重装、容器迁移、备份恢复后沙盒路径变化，书架记录还在但文件打不开；书签/进度用 lastPathComponent 做 key，也会跟着错位。

建议：只存相对 Documents 的路径；打开时用当前容器拼绝对 URL；加一次启动自愈迁移。

高正文没有 VoiceOver 可访问元素+

证据：TextRenderView.swift 是纯绘制视图，没有 isAccessibilityElement / accessibilityElements；TextVC.swift:99-109 只给页码和章节标题加了标签。

影响：VoiceOver 用户能听到「第 12 页」「章节：第一章」，但读不到正文——对阅读 App 是核心功能缺失。

建议：按页/段生成 accessibility elements，提供「朗读当前页」「下一段」等自定义动作；至少先让当前页正文可被逐段朗读。

高0 测试 target，核心逻辑没有回归网+

证据：xcodebuild -list 只列出 Mini Read 一个 target / scheme；工程无 Tests 目录。

影响：ChapterHTMLParser、PaginationConfig.stableDigest、ReadingStatsEngine、进度口径都是可测纯函数，却没有一条断言；每次改分页/缓存都可能静默回归。

建议：先加 MiniReadTests，覆盖解析块模型、摘要稳定性、跨午夜统计、进度分母、锚点换算。成本低，收益最高。

中全书页码索引可能造成首开性能尖峰+

证据：MainViewController.swift:1593-1644 在首屏后逐章排版全书算页数；每章都要走完整 TextKit 排版。

影响：大书/多图 EPUB 首开可能 CPU 飙高、内存上涨、翻页掉帧；目前没有进度反馈或取消入口。

建议：限制并发、加可取消的索引任务与进度提示；或只索引当前章 + 用字符数估算全书页数。

中设置字段漂移，用户会以为功能已生效+

证据：30+ 个字段没有真正影响阅读体验，例如 defaultHighlightColor、libraryViewMode、preloadPages、appLanguage、dateFormat；SettingsProfile 还会把这些值一起导入导出。

影响：用户改设置没有任何变化，或换配置文件后以为阅读行为变了；设置页越完整，信任损耗越大。

建议：每个字段做「消费者或删除」二选一；短期可在未接线的设置项上加「即将支持」标记，长期清理 profile 字段。

中单文件 EPUB 的进度粒度只有 0/1+

证据：ContentsPanelModel.swift:292-298 用 allSrcs.count 做分母；BookModel.swift:103-109 用已读 src 数做分子。单文件多锚点 EPUB 只有一个 src。

影响：打开即 100%，书架无法反映书内位置；多文件书按章跳变，长章内也不平滑。

建议：在章进度之上加页/字符偏移的二级进度；书架可显示「第 3 章 · 42%」。

中无本地化资源，界面中英混排+

证据：工程无 .xcstrings / .lproj；TabScreens.swift:219-243 使用 “Search your library / Find books by title…” 等英文文案；appLanguage 字段无消费者。

影响：中文用户看到中英混排；切换语言设置无效；日期格式也不受控。

建议：先建 String Catalog，把阅读器、书库、设置三块文案收口；再接 appLanguage 与 dateFormat。

中图片与分页缓存没有字节级上限+

证据：图片以 NSTextAttachment 进入整章富文本并写入 PaginationCache；ChapterLRUCache.swift:13-27 只按章数（5）限制；preloadPages / imageCacheQuality 未消费。

影响：漫画/画册类 EPUB 可能一张图就占几十 MB；LRU 按章数而不是字节数，内存峰值不可控。

建议：解码按屏宽下采样；缓存按字节限额；把 imageCacheQuality 真正接进 ChapterTypography。

低iPad 强制卷曲，Reduce Motion 强制滑动+

证据：MainViewController.swift:1802-1836 的 resolvedTurnStyle；翻页设置页 footer 也明确写了这条规则。

影响：用户偏好被覆盖；slide 实际是 UIPageViewController.scroll，不是 Apple Books 的离散滑动。

建议：把「无障碍降级」与「设备形态」作为默认值而不是硬覆盖；补一个真正的离散滑动样式。

结论
Mini Read 的问题不是「不会做阅读器」，而是「做了一半的功能太多」。分页、目录、书签、统计已经具备产品级骨架；下一步应该把标注、搜索、设置接线和可访问性做成真正的闭环，再用测试把这条链路锁住。这样比继续增加设置页或动画样式更能提升完成度。
