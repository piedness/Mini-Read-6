## 书架卡片：收藏角标延后出场（`Views/BookContentUI/BookCard.swift`）

**问题**：角标由 `if isFavorite` 直接驱动。contextMenu 里一点，模型当场翻转，
角标就在**同一帧**插入——此时菜单还在收起，缩放弹入整个被菜单盖住，
观感是"出现得太早 / 莫名其妙"。

**改法**：把「数据状态」与「可见时机」拆开。
- `@State isFavoriteBadgeVisible` 独立于 `isFavorite`；两个 `init` 用
  `State(initialValue:)` 就地取初值（首帧不闪、不弹）。判据抽成
  `static func isFavorite(in:)`，init 与 body 共用，避免分叉。
- `syncFavoriteBadge(to:)`：收藏延后 240ms（`favoriteBadgeRevealDelay`，菜单收起约 0.2s）
  再弹；取消收藏立刻淡出。用自增 token 作废在途任务，不用 `Task?` 句柄
  （句柄在取消分支里容易漏清，会永久跳过兜底同步）。
- 去掉 `.animation(value: isFavorite)`，改 `withAnimation` 显式下发：
  出场 spring(0.34/0.62) / 退场 easeOut(0.16)；reduceMotion 下均为 nil。
- 保留 `.onChange(of: isFavorite)` + `.onAppear` 兜底。

**追加（同日）**：角标再叠一层「场景」状态——看书时让位。
- `@State isFavoriteBadgeFadedForReader` + `favoriteBadgeReaderToken`；
  `.onChange(of: isShowFullscreen)` 驱动 `syncFavoriteBadgeForReader(isPresented:)`。
- 开书：`easeOut(0.3)` 立刻淡出（赶在 zoom 推走封面之前）；
  合书：等 `favoriteBadgeReturnDelay`（250ms，让封面先落位）再 `easeInOut(0.5)` 淡回。
- 只改 `.opacity`，不动 frame/scale，卡片布局与网格排布零影响；
  透明度不属于前庭刺激，reduceMotion 下保留淡入淡出、仅压到 0.2s。
- 两层状态互不覆盖：`isFavoriteBadgeVisible` 管「是否收藏」，faded 管「是否在看书」。

**验证**：xcodebuild Debug / iPhone 17 Pro 模拟器 → BUILD SUCCEEDED，
BookCard.swift 0 warning。工程无测试 target（pbxproj 只有一个 application target）。

**构建配方（重要，替代此前的 `swiftc -typecheck`）**：本机沙箱禁止嵌套
`sandbox-exec`，`xcodebuild` 会卡在 "Resolve Package Graph"。两条绕过同时用即可完整构建：
1. `defaults write com.apple.dt.Xcode IDEPackageSupportDisableManifestSandbox -bool YES`
   （构建后 `defaults delete` 还原）；
2. 宏改为进程内展开：`OTHER_SWIFT_FLAGS` 里对 8 个 dylib 各加一组
   `-Xfrontend -load-plugin-library -Xfrontend <dir>/libXxxMacros.dylib`，
   `<dir>` = `iPhoneOS.platform/Developer/usr/lib/swift/host/plugins`
   （SwiftData / Observation / SwiftUI / Swift / Foundation / Previews / AppIntents / TipKit）。
   `-in-process-plugin-server-path` 无效——驱动会覆盖成平台版 swift-plugin-server。

## 修复「点 Save Cover 后封面闪几下」

**根因**：`BookCardView.body` 里同步 `UIImage(contentsOfFile:)` 取封面。存相册
这条链路会让卡片重绘 3 次（菜单收起 / 成功勾出现 / 1.4s 后勾消失），每次重绘都
新建一张**未解码**的 UIImage，图层内容换掉的那几帧就是空白；再叠上
`premiumHardcoverStyle()` 的 blendMode + 双层阴影离屏合成，空白帧被放大成可见闪烁。

**改法**（3 处，未新增文件）：
- `BookCard.swift`：封面改为 `@State coverState`（loading / loaded / unavailable）
  + `.task(id: coverURL)` 后台读一次；`body` 只查内存缓存，不碰磁盘。开本比例走
  `CoverThumbnail.aspect(url:)` 读文件头，保证骨架与真封面同形状、不跳高度。
  存相册改为按需读原图（`Data` 跨线程、`UIImage(data:)` 懒解码），不再从 body
  捕获全尺寸位图。徽标的进出动画从 `withAnimation` 收窄成 overlay 上的
  `.animation(value:)`，不再把整张卡片拖进同一事务。
- `CollectionCover.swift`：`CoverThumbnail` 加 `natural` / `cachedNatural`（保持
  原开本不裁切）与 `aspect`（只解析文件头）；缓存补 `totalCostLimit = 96MB` 并按
  字节记 cost——原实现只有 countLimit=300，混入书架大图后会失控。
- 顺带修掉一个既有缺陷：工程里根本没有 `coverTest1` 这个资源，所以「无封面」的
  书以前渲染成零尺寸（书架上完全看不见）。现在给不透明中性底 + `book.closed`
  图标，仅 `.unavailable` 时显示图标（加载中显示会闪）。

**验证**：
- `xcodebuild` Debug/iOS Simulator `BUILD SUCCEEDED`；除 `ReadingBackground.swift:256`
  一条既有警告外无新增 warning。
- 抽出真实的 `CoverThumbnail` 编译成模拟器可执行文件，用 EPUB 里的 550×800 封面
  实测：aspect=0.6875 正确、降采样不超预算且比例不漂、二次调用命中缓存（同一
  实例）、不同像素档位不串键、文件缺失返回 nil、裁切通道仍输出 1:1。
- 模拟器实跑：书库 1 本书，真实封面按原开本正常渲染（圆角/书槽/阴影俱在），
  封面文件缺失时走兜底不崩。

**环境坑**：`System Events` 无辅助功能权限，脚本点不动模拟器；临时把
`Tabs.swift` 的默认 tab 改成 `.library` 截图，已还原。每装一次 `simctl install`
容器 UUID 都会变，需重新 replace 一遍 store 里的绝对路径。

## 长按封面 contextMenu 抬起卡顿（Step 2 已落地）

**根因判断**：抬起动画是 UIKit 对快照做 `CATransform3D` + 圆角插值，不是 SwiftUI 动画，
`.animation()` / `withAnimation` 无效。三个来源：快照太贵（3 层渐变 + 2 个 blendMode + 2 层影）、
快照与源视图几何不一致（菜单挂在含元信息行与 5pt padding 的整卡上）、
缺 `contentShape(.contextMenuPreview:)` 导致圆角从系统默认跳到 4pt。

**已改**：
- `BookCard.coverCard`：`contextMenu` 从整卡 VStack 移到 `sizedCover(image)`；
  新增 `.onGeometryChange` 记录 `coverSize`；`.contentShape(.contextMenuPreview, RoundedRectangle(4))`。
- 新增 `bookContextMenu`（菜单项原样搬出）与 `coverMenuPreview`（只含位图 + 显式 frame + 4pt 裁切，
  无 shadow / blendMode / 文字）。frame 必须显式：`UIImage(cgImage:)` scale = 1，1000px 图的 ideal size 是 1000pt。
- `PremiumHardcoverModifier.cornerRadius` 提为 `static let`，预览/命中形状/修饰器共用一份。
- 两枚角标加 `.allowsHitTesting(false)`，避免盖在封面上吃掉长按。

**验证**：模拟器 Debug 构建通过，两文件实际重编、无新增警告（唯一警告是 `ReadingBackground.swift:256` 原有 actor 隔离）。
未能自动验证长按手势：模拟器无辅助功能权限，无法注入触摸，需真机/手动长按确认。

**待办（若仍卡）**：`premiumHardcoverStyle` 加 `.compositingGroup()`（让 blend 在组内解析，快照才和屏幕一致）；
`matchedTransitionSource` 与 contextMenu 同视图的冲突需做对照实验；VoiceOver 的自定义 actions 需复验
（菜单从卡片移到封面后，`.accessibilityElement(children: .combine)` 是否仍合并菜单动作）。
