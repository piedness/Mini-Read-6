# 2026-11-16

## 修复：目录 fragment 被丢弃（同文件多目录项全塌到章首）

**根因**：`EPUBPath.clean` 在 `#` 处截断，`EPUBTOCEntry` 无 fragment 字段，
`TOCJumpRequest` 只有 src/characterOffset，目录点击一律走章首。

**改动链路（8 个文件）**：
- `ChapterHTMLParser.swift`：新增 `ChapterAnchor`（id + 块下标）/ `ParsedChapter`，
  `parseChapter(_:)` 在块级遍历前与行内节点处登记 `id`/`<a name>`，`parse(_:)` 保留为薄包装。
- `ChapterTypography.swift`：新增 `typeset(...) -> TypographyResult`（含 `blockOffsets`，
  在追加每个块前记录 `result.length`）与 `anchorOffsets(anchors:blockOffsets:textLength:)`；
  `contentSchemaVersion` 升到 `chapter-blocks-v4`（旧缓存无锚点表，必须失效一次）。
- `ChapterLayout.swift`：保存 `anchors: [String: Int]`，新增 `characterOffset(forAnchor:)`
  （精确匹配 + 大小写不敏感兜底）。
- `PaginationCache.swift`：`DiskEntry.anchors`（可选）随富文本一起落盘/解档。
- `ChapterRender.swift`：`parseChapter` → `typeset` → `anchorOffsets` → `ChapterLayout(anchors:)`；
  版权页排版不产锚点（块与文本已重排）。
- `EPUBNavigation.swift`：`EPUBPath.fragment(_:)`；`EPUBTOCEntry.fragment`；
  `resolve` 仅在 src 落地时保留 fragment，分组项借用第一个子项的 src **和** fragment。
- `ReaderTOC.swift`：`SubChapter.anchor`、`TOCJumpRequest.anchorID`、`makeChapters` 透传。
- `ContentsPanelModel.swift` / `MainViewController.swift` / `TextVC.swift`：
  `selectSubChapter` 带 anchorID；`navigateTo(src:anchorID:characterOffset:)` →
  `jumpTo` 内把 anchor 解析成本章字符偏移再复用书签落页路径；首屏前跳转新增 `pendingAnchorID`。

**验证**：
- 全量 `swiftc -typecheck`（114 文件，iOS SDK 26.5 / target 18.6，真依赖模块）0 error。
  xcodebuild 在本机被包解析的嵌套沙箱拦住，无法跑完整构建。
- 真实解析器 + Kanna 运行时夹具：`#sec1`→block0、`#sec%202`→解码为 `sec 2`、
  分组项借到子项 fragment、无 fragment 仍为 nil；端到端 `EPUBNavigationParser.parse` →
  `makeChapters` 的 anchor 全部正确。

**遗留（未在本轮处理）**：单文件 EPUB 的进度模型仍按文件计（一章一文件的假设），
`totalChapterCount` 含封面/版权页导致书架进度到不了 100%，见 2026-11-16 的代码评审结论。
