## 分页缓存：写盘与清盘的竞争修复（`purgeAllBookData` 审查的落地项）

**问题**：`PaginationCache.save` 把编码后的 JSON 派发到 `DispatchQueue.global(.background)`，
`purgeDiskContents` 在另一条队列删同一目录。在途的写可以落在清理之后，给已删书留下
一个读不到也删不掉的 `.paginationcache`（`StorageAnalyzer` 只扫 extracted/backup，孤儿检测看不见）；
若落在复测之后，UI 报"已全部清除"且 `hasBookData` 变 false → 入口永久禁用。

**改法**（只动缓存层，视图层不变）：
- `PaginationCache` 新增 `diskLock: NSLock` + `diskGeneration: Int`；
  `save` 在**调用时**同步捕获代次（不能放后台块里读，否则编码期间的清盘会被误判成新写），
  后台块内「校验代次 + 写文件」同锁完成；
- 新增 `purgeDisk()`：同锁内 `diskGeneration &+= 1` + 删目录，作为**唯一清盘入口**；
  `purgeDiskContents` 改为 `private static`，禁止绕过；
- `invalidateAll` 的后台块改调 `self.purgeDisk()`；
- `StorageCleaner.purgePaginationCache()` / `purgeAllBookDataOnDisk()` 改调
  `PaginationCache.shared.purgeDisk()`。

**语义**：清盘前排队（已捕获旧代次）的写一律作废，清盘后的新写照常允许——新导入的书仍能缓存。
残余窗口：`save` 的调用本身恰在删盘循环的几微秒内（需阅读器已关但其章节加载刚好完成），
由 `remaining` 复测 + "请重试"文案兜底。

**验证**：`xcodebuild` Debug / generic iOS Simulator → BUILD SUCCEEDED，0 新增 warning
（`PaginationCache.swift:237` 的 `Encodable` 隔离告警是原有代码模式固有，已用最小样例复现确认）。

**未处理（审查清单里剩下的独立缺陷）**：`StorageAnalyzer.directorySize` 的 `.skipsHiddenFiles`
统计口径 vs 整目录删除、`rollback()` 波及全局 mainContext、全表 `@Query`、主线程批量删除。

## 「清除所有书籍数据」按钮可用性重构（承接上一条）

**用户诉求**：保证按钮可用、没有 bug。

**根因（按钮为什么会变灰且再也点不了）**：
1. `bookDataBytes()` 走 `directorySize` 的 `.skipsHiddenFiles`，而清理是整目录删除。
   残留只剩隐藏文件时统计为 0 → `hasBookData == false` → 按钮永久禁用，
   孤儿检测同样跳过隐藏文件，这批文件从此任何 UI 都删不到。
2. `modelContext.rollback()` 是全局 mainContext 的，会把别处未提交的改动一起丢；
   回滚后 `@Query` 未必立刻恢复，若列表停在空态，按钮同样永久禁用。
3. `.disabled(isMeasuring || ...)`：全盘体积扫描期间按钮一直灰着，大库要好几个扫描秒。

**改法（5 个文件）**：
- `StorageAnalyzer.directorySize(_:skippingHiddenFiles:)` 新增参数，默认 `true` 保持分类统计口径；
- `StorageCleaner.bookDataBytes()` 传 `false`（与清理口径一致）；
- `StorageCleaner.purgeAllBookDataOnDisk()` 返回 `(freed, remaining)`，`freed` 改为**前后实测差值**
  而非删除前估算；
- `deleteDirectory` 改为 `@discardableResult -> Bool`，路径不存在（`NSFileNoSuchFileError`）
  视为成功，不再刷假错误日志；
- `ExperimentalFeaturesView` 重写清除段：
  · 两个全表 `@Query` 换成 `fetchCount`（不物化十万级对象），判空用 `derivedRecordCount`；
  · 删除集合改为操作内 `FetchDescriptor` 重新 fetch（不依赖视图快照，避免对已失效对象 delete）；
  · 删前先 `save()` 落一次盘，把 `rollback()` 的波及面限制在本次删除；
  · `measureID` 代次作废在途测量，避免旧数字覆盖清盘后的 0；
  · `PurgeGate`（进程级 `@MainActor` 静态标记）防视图 pop 重建后的二次触发；
  · 按钮不再被 `isMeasuring` 挡住，只受 `isPurging || !hasBookData` 约束；
  · 成功/失败加 `triggerNotificationHaptic`。

**验证**：`xcodebuild` Debug / generic iOS Simulator → BUILD SUCCEEDED。
该页隔离告警从 3 条降到 2 条（`bookDataBytes` / `purgeAllBookDataOnDisk` 从 `Task.detached` 调用，
是工程 `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` 下的既有模式，Swift 5 模式不影响运行）。

**仍存在的已知缺陷**：导入 staging 与整库清除仍无互斥（`EPUBImportQueue` 与清盘互不知情）——
极端时序下会留下指向空目录的"幽灵书"。彻底修需要一个跨 `Tabs.swift` 与清除入口的
"书库变更闸门"（导入计数 + 清除前检查），本次未做。

## 「点全部清除闪退」修复：批量删除改用独立 ModelContext

**现象**：点 alert 的「全部清除」直接闪退。模拟器无崩溃报告（用户应在真机）。

**定位过程**：
1. 用 macOS 命令行 + 同款模型复现数据层（内存库 / 文件库各一次，含 cascade + 多对多 nullify）
   → 全部正常，排除 SwiftData 批量删除本身。
2. 在 App 里加临时 `-autopurge` 调试入口（ContentView 用 fullScreenCover 盖住，保证首页仍活着），
   播种 30 本书 + 300 条进度 + 真实磁盘文件（7.7MB，含 `.DS_Store`）→ **仍未崩**。
3. 结论落在**时序**而非数据：`modelContext.delete()` 立刻把对象标记为已删，但 `@Query`
   要到下一次刷新才移出结果集。这段窗口里只要还有活着的视图重新求值并读了书的属性
   （书架卡片、书单封面、统计卡都会），SwiftData 就以 "model instance was invalidated" 终止进程。
   删一本书窗口只有一帧，**一次删光整库时整个首页都站在窗口里**；`withAnimation` 还会让
   正在退场的卡片在动画期间重新求值，进一步放大。

**改法**（`ExperimentalFeatures.swift`）：
- 批量删除移到 `Task.detached` 里，用 `ModelContext(modelContext.container)` 独立上下文
  fetch + delete + save；主上下文不再自己删，只在后台 save 后合并（与 `@Query` 刷新同一时刻失效）。
- 去掉包裹删除的 `withAnimation`（这个 List 不展示书，动画没有收益，只延长退场视图寿命）。
- 删前那次 `modelContext.save()` 与 `rollback()` 一并删除：独立上下文失败时主上下文压根没动过。
- `deleteDerivedRecords` 改为 `static func (in:)`，可跑在任意上下文上。

**验证**：模拟器 iPhone 17 端到端跑通 —— 30 本书 + 7.7MB 真实文件 → 0 本 / Zero KB /
按钮自动禁用 / 文案「已删除 30 本书及相关数据，释放 7.7 MB」，无崩溃。
`@Query` 合并正常（`books=0`）。临时调试入口已全部移除，`grep harness|PurgeDebug|autopurge` 为空。
清理后 `xcodebuild` → BUILD SUCCEEDED，warning 数不变（19）。

### 短行下划线撑满整行修复

- 原因：选区包含行尾 `\n` 时，TextKit 的 `boundingRect` / `enclosingRects`
  会把换行当成「延伸到行尾」的控制字符，两字短行返回整行宽（复现：短句+换行
  bounding 宽 290，裁剪后 31.75）。
- 修法：`ChapterLayout.lineRects` / `lineFragmentGeometries` 改为逐行枚举，
  先按组合字符裁掉行尾空白与换行，再取 `boundingRect`；空行直接跳过。
  该几何同时服务下划线、底色、选区边框、手柄、边注与无障碍，全部一起修正。
- `ChapterLayout` 新增 `plainText` 缓存，避免逐行裁剪时反复桥接整章文本。
- 验证：macOS TextKit 复现脚本通过（短行 31.75、空行跳过、长行中间两字 31.75）；
  全量 typecheck 0 error；WMO 编译成功。

## 阅读器加载态：ProgressView → ReaderLoadingView

**问题**：`BookContent.swift` 里打开书时的 `ProgressView()` 浮在无背景的 ZStack 上，
zoom 转场期间透出书库、纸面迟到；暗纸面（夜读）会先浅后黑闪一下；
系统转圈与 `ReaderOpenFailureView` 的衬线排版毫无关系；VoiceOver 无任何信息。

**做法**：新增 `Views/BookContentUI/ReaderLoadingView.swift`
- 背景 = `AppSettings.readingBackground` 的纸面（纯色 `fillColor` 打底 +
  `ReadingBackgroundImageLoader.imageAsync` 异步铺纸纹，0.18s 淡入）。
  与 `PageBackgroundView` 同一张图、同一 `scaleAspectFill` 几何，切换不错位；
  顺带把 2048 位图预热进缓存，阅读器建页时直接命中。
- 书名/作者用 `resolveReadingSwiftUIFont`（阅读字体）+ `ReadingTextTone` 墨色，
  居中、只用字号分层（不加粗，与 `CoverPageViewController` 同一判断）；
  字号 `@ScaledMetric` 基准 28 / 15，版心左右 32 / maxWidth 440（与失败页同度量）。
- 指示器 `InkActivityIndicator`：30pt、1.75pt 墨线弧 + 0.12 淡环，1.0s 匀速旋转；
  `reduceMotion` 下改为 1.1s 呼吸（不旋转）。
- 内容 0.22s 淡入（与 `readerRevealAnimation` 同长），纸面不淡入（必须首帧不透明）。
- 整屏一个 a11y 元素：`正在打开《书名》，作者`。

**验证**：全量 typecheck 0 error / 0 warning；`swiftc -c -wmo -O` 编译通过（10MB .o）；
用桩数据在 iPhone 17 模拟器渲染截图核对版式与旋转动画（相邻两帧 ring 区域有差异、
其余区域 0 差异）。`xcodebuild` 在本机被 sandbox 挡住（package manifest 编译要
`sandbox-exec`），只能用 swiftc 直编验证——**以后同环境验证走这条路**：
`swiftc -typecheck -disable-sandbox -sdk $(xcrun --sdk iphonesimulator --show-sdk-path)
-target arm64-apple-ios18.6-simulator -I <DerivedData>/Build/Products/Debug-iphonesimulator`，
ZipArchive 需自建 modulemap（`-I /tmp/zipmod`，指向 checkouts 里的 SSZipArchive）。
